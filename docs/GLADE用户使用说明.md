# GLADE 用户使用说明

GLADE 用于辅助设计微生物合成目标化合物的方案：先判断底盘细胞能提供哪些前体，再寻找需要补充的代谢反应、选择催化这些反应的酶，最后设计表达序列和质粒。

如果你的问题是“想让大肠杆菌合成某个化合物，需要引入哪些酶，怎样把它们放进质粒？”，可以按本指南逐步操作。每一步都说明要解决的生物学问题、操作方法和结果含义。

GLADE 最终提供的是**候选合成路线、待表达的蛋白及其编码序列、表达元件组合和带注释的质粒设计文件**。路线可行性、酶功能和表达水平仍需实验确认；程序完成设计不代表已经获得产物或确定了产量。

全文示例使用项目目录 `F:\myproject\glade`、目标化合物编号 `C00811` 和配置文件 `demo01.json`。实际操作时，请换成自己的项目位置和目标编号。

### 先认识几个常用名称

| 文档中的名称 | 在实验设计中表示什么 |
|---|---|
| 底盘 | 用来生产目标化合物的宿主细胞，本指南默认使用大肠杆菌 |
| 可提供的代谢物／可达集合 | 在指定培养基和代谢模型条件下，细胞被预测能够供给的代谢物，可作为合成路线的前体 |
| 主酶 | 直接催化所选合成路线中反应的酶 |
| CDS | 蛋白质的 DNA 编码序列；生成 CDS 就是为选定蛋白准备可用于构建的编码序列 |
| 表达盒 | 从启动子到终止子的一段表达单元，可包含一个或多个 CDS；本流程为每个 CDS 配置一个 RBS |
| RBS | 核糖体结合位点，用于控制对应 CDS 的翻译起始 |
| 质粒骨架 | 承载表达序列的载体部分，包含复制和抗性等功能 |
| manifest／设计清单 | 程序自动维护的项目记录，保存你已选用的路线、蛋白、元件和结果文件位置 |

操作中最常见的两类命令是：`info` 用于**查看结果**，`write` 用于**确认选用某个方案**。看到候选列表后，通常还需要运行相应的 `write`，后续步骤才会使用你的选择。

路线编号、主酶组合编号、表达盒分组方案编号和表达盒编号分别对应不同内容。示例中的 `1` 和蛋白编号 `P21683` 都只是演示，请以自己结果中的编号为准。

## 1. 运行准备

### 启动环境

以下步骤假定 GLADE 已安装好。首次安装或需要配置网络服务、RetroPath 时，请先参考 [部署教程](GLADE部署教程.md)。

项目使用 Python 3.12。打开 PowerShell，在下面两行命令中将项目路径换成自己的安装位置，然后逐行执行：

```powershell
cd F:\myproject\glade
& .\.venv\Scripts\Activate.ps1
```

第二行用于启用项目已安装的运行环境。如果提示激活脚本被阻止，可先执行下面的命令，再重新执行激活命令：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
```

**后文所有命令都在项目根目录执行**，即包含 `main.py` 的目录。复制命令时，不需要复制代码框中的 `powershell` 标签。

如果部署时使用的是 `uv`，也可以把后文的 `python main.py` 替换为 `uv run python main.py`；这种方式无需手动激活环境。

### 创建输入配置

先确定要合成的目标化合物，记录其 KEGG Compound 编号。程序通过这个编号识别化合物，不能直接填化合物中文名或英文名。

在项目的 `inputs` 文件夹内新建文本文件，命名为 `demo01.json`，写入以下内容并保存为 UTF-8 编码。注意文件扩展名是 `.json`，不是 `.json.txt`。

```json
{
  "target_name": "C00811"
}
```

将 `C00811` 替换为目标的 KEGG Compound 编号。虽然字段名是 `target_name`，这里填写的是**化合物编号**，格式为大写 `C` 加五位数字。

所有命令的 `-i`（与 `--input` 等价）后只填配置文件名，例如 `-i demo01.json`。程序会自动到 `inputs` 文件夹查找，不要填写 `inputs/demo01.json` 或完整路径。

当前默认底盘是 *E. coli* MG1655，使用 iML1515 基因组尺度代谢模型和 `data/mediums/default_medium.json` 中的培养基设置。代谢模型可以理解为程序用于计算细胞代谢能力的反应网络；它的预测取决于模型和培养基条件。上面的配置只指定目标，不会自动更换宿主或培养基。

## 2. 常规完整流程

完整流程可以分成三段：**选代谢路线和蛋白 → 准备表达序列 → 设计质粒及组装方案**。

```text
确定目标 → 判断底盘能提供哪些前体 → 搜索并选定合成路线
→ 选择催化各步反应的主酶
→ 生成编码序列（CDS）→ 按需调整 GC、酶切位点或连续重复碱基
→ 确定哪些基因共同表达 → 上传或选择启动子、RBS 和终止子
→ 拼接完整表达序列 → 设计质粒并导出理论组装结果
```

### 2.1 判断底盘能提供哪些合成前体

这一步回答：“在当前培养条件下，宿主自身能提供哪些代谢物，哪些可以作为目标合成的起点？”

运行底盘分析：

```powershell
python main.py chassis -i demo01.json
```

完成后可以查看使用的模型、培养基和代谢物摘要：

```powershell
python main.py info -i demo01.json --chassis
```

这些结果是**模型预测的供给能力**，不等于培养液中已经检测到这些代谢物，也不表示它们能在同一条件下同时大量积累。通常接着搜索合成路线。

若提示目标已可直接供给，表示当前模型和培养基条件下，目标不需要新增合成路线。这不代表现有菌株已经达到所需产量，应结合实际菌株和实验检测结果判断。

### 2.2 搜索并选择路线

这一步回答：“从底盘能提供的前体出发，还需要补上哪些反应，才能生成目标化合物？”

默认从 KEGG 反应数据中寻找候选路线。下面三条命令依次用于搜索、查看路线列表、查看路线 1 的各步反应：

```powershell
python main.py gap -i demo01.json -d 0
python main.py info -i demo01.json --gap -d 0
python main.py info -i demo01.json --solution 1 -d 0
```

选择路线时，重点检查起始前体、每一步的底物和产物、反应方向，以及所需的辅因子。步骤较少的路线可以优先查看，但仍需判断各步反应是否适合你的宿主和实验条件。

KEGG 方向筛选由 `src/config/run_config.py` 中的 `self.unpre_re_reaction` 控制，默认值为 `3`，`expand` 和 `gap` 共用：

| 值 | 允许进入候选路线的反应方向 |
| --- | --- |
| `0` | 不增加方向限制，左到右和右到左均可参与 |
| `1` | 排除标记为 `disfavored` 的方向 |
| `2` | 只允许标记为 `favored` 的方向 |
| `3` | 在模式 `2` 基础上禁止右到左，只允许 `left_to_right` 且标记为 `favored` 的方向 |

方向限制从 `0` 到 `3` 逐级收紧；模式 `3` 包含模式 `2` 的全部限制。无解时不会自动放宽方向限制。方向相对于 KEGG 方程的书写顺序；`favored`、`neutral`、`disfavored` 来自程序的启发式规则，不是实际条件下的 ΔG 计算。模式 `0` 仍保留原有的步数、辅因子负担和环路等筛选。

修改方向策略后，如需使用 `-d 1` 或更深的 KEGG 扩展集合，应先使用同一配置重新运行 `expand`；旧格式或策略不匹配的扩展缓存不能直接复用。该设置不改变底盘 GEM 自身的通量边界和 RetroPath 预测反应规则。

决定使用路线 1 后，将它确认为本项目的合成路线：

```powershell
python main.py write -i demo01.json --solution 1 -d 0
```

`write` 会把选择保存到设计清单，后续主酶筛选将基于这条路线。`1` 是示例路线编号，不是反应步数。

如需进一步判断路线在代谢模型中能否运行，可在确认前或确认后做 [路线验证](#32-验证路线)。验证是可选步骤；纯 KEGG 路线确认后再验证时，匹配的验证结果会自动回写清单。没有合适路线时，可尝试 [底盘扩展](#31-扩展底盘可达集合) 或 [RetroPath](#33-使用-retropath)。

**同一批路线的搜索、查看、验证和确认必须使用相同的 `-d`。** `-d 0` 表示从未经额外反应扩展的底盘供给能力出发；`-d` 不是合成路线的反应步数，扩展深度的含义见第 3.1 节。

### 2.3 选择主酶

路线确定后，需要为其中待引入的反应选择具体酶蛋白。这一步将“需要某个反应”转化成“需要表达哪些蛋白”。

先检索各步反应的候选主酶，并查看结果：

```powershell
python main.py main-enzyme -i demo01.json
python main.py info -i demo01.json --main-enzyme-candidates
```

查看时重点关注反应是否匹配、催化方向是否有支持、蛋白来源。候选排名是筛选参考，不是对酶活或产量的实验保证；标记为“需要复核”或方向待确认的候选应重点检查。

随后生成主酶组合。每个组合代表一套覆盖所需反应的蛋白选择：

```powershell
python main.py main-enzyme-sets -i demo01.json
python main.py info -i demo01.json --main-enzyme-sets
python main.py write -i demo01.json --main-enzyme-set 1
```

写入时会先为选中蛋白准备 `inputs/protein_sequences/<蛋白编号>.fasta` 和同名 `.json`，复用完整且一致的本地缓存；缺失时联网补齐。序列必须与主酶候选结果一致，冲突或下载失败时保留原清单。

设计清单的 `main_enzyme_selection` 仅保存 `selected_solution_id`（路线编号）、`reaction_assignments`（按反应编号组织的已选蛋白）和 `review_required_step_indexes`（待复核步骤）。每个反应记录 `step_indexes` 和 `proteins`，每个蛋白记录 `accession`、`sequence_file` 与 `selection_source`（`automatic` 或 `manual`）。同一反应下的蛋白全部属于已选蛋白；同一反应出现多次时合并步骤和蛋白，同一蛋白用于多个反应时共享序列，并只生成一份 CDS。

自动组合写入更新自动选择部分，并保留当前路线已有的人工记录。主酶重新计算时保留人工记录，切换路线则清理旧选择。蛋白注释保存在同名 JSON 中，评分及证据保留在主酶分析文件中；已选蛋白的读取不依赖组合编号或组合文件。旧版清单仍可读取，重新写入或实际添加人工蛋白时转换，其他操作不会自动迁移旧版清单。

生成主酶候选前，程序扫描当前路线的已选蛋白。某个反应只要有 `selection_source=manual`，就保留该反应下的整组蛋白（包括原有自动蛋白），跳过该反应的自动检索。纯自动记录仍重新检索。人工已选蛋白的本地文件缺失、损坏或序列冲突时，在清理旧结果前报错，不会改用自动候选。

含跳过反应的候选结果使用 `main_enzyme_selection.v8`，在 `preselected_reactions` 中单独保存已选蛋白与序列摘要；这些蛋白不参与候选排名，也不占用每步候选名额。没有跳过反应时继续输出 v7。`info --main-enzyme-candidates` 会标明“人工已选，跳过检索”。

v8 候选可继续执行 `main-enzyme-sets` 和 `write --main-enzyme-set N`，组合结果保存为 `main_enzyme_sets.v8`。固定反应下的全部蛋白始终保留，仅搜索其余反应。组合的蛋白数量、物种数量和 Reviewed 比例按完整去重集合计算；反应匹配、蛋白、底盘分数及风险计数只评估本次自动选择部分。已选蛋白只有在也是其他反应的有效候选且序列一致时才可复用，不会因“已经选中”而推断额外催化能力。

组合搜索和写入前都会校验已选快照、当前路线、基因组及本地序列；记录或文件变化时先重新生成候选。写入复用固定蛋白的原文件，只为新蛋白准备文件。所有需要选酶的反应都已选齐时，组合阶段报告 `already_selected`，不搜索、不生成组合，也无需再次 `write`；当前清单保持不变。普通 v7 结果继续使用原有流程。

示例选择组合 1。确认后，可以用 `python main.py info -i demo01.json --proteins` 查看已选蛋白及其编号。

#### 为反应添加本地蛋白

写入路线后，可以在检索候选、生成组合或写入选中组合之前或之后，直接为某个反应追加已选蛋白：

```powershell
python main.py protein add -i demo01.json -r R02061 -f P22873.fasta
python main.py protein add -i demo01.json -r R02061 -f MY_ENZYME.fasta
```

`-r/--reaction` 必须是当前路线中的反应，`-f/--file` 只填 `.fasta` 文件名，程序从 `inputs/protein_sequences`（或配置输入目录的同名子目录）查找，不按当前工作目录查找。文件必须恰好包含一条非空、标准氨基酸序列。编号使用文件名去掉扩展名后的大写形式，支持自备蛋白的本地编号；本地 FASTA 标题无需 UniProt 编号，文件内容与路径保持原样。

`add` 不联网。有同名 JSON 时严格校验，损坏或冲突时报错；没有时自动补建本地注释 JSON，保存长度和序列 SHA-256，名称、来源物种、Reviewed、辅因子等未知信息为 `null`，显示为“未知”。本地注释不包含伪造的 UniProt 原始记录，也不充当 `protein download` 已获取 UniProt 记录的缓存。之后读取时仍要求文件完整且一致，不能把已损坏或丢失的注释当成未知继续使用。

同一 R 下已有蛋白时追加到末尾；同编号、同序列已存在的自动记录在原位置改为人工来源，人工记录重复添加不变。同编号对应不同序列时报错。该 R 出现多次时应用到全部对应步骤；一个蛋白用于多个 R 时分别执行添加，共享原序列文件和一份 CDS。人工指定涉及的步骤会并入待复核列表，原有其他选择和复核信息保留。

已有有效候选时，`add` 会更新 v8 已选快照，保留其他反应的候选与排名，并清理旧组合 JSON/CSV；可直接重新运行 `main-enzyme-sets`。若没有可复用的候选，或候选路线、基因组、文件已过期，人工指定仍写入清单，但需要先运行 `main-enzyme`；旧候选不能继续用于组合。重复添加相同人工记录不修改文件、不清理组合。添加失败时恢复清单、补建注释、候选和组合文件。

已选蛋白的审校状态允许未知，组合 Reviewed 比例为明确 `true` 的蛋白数除以完整去重蛋白数，未知物种不计入物种数量；评分范围仍只包含自动选择部分。此功能处理选酶阶段，本次未扩展已生成 CDS、表达盒后的失效处理。

#### 删除反应中的已选蛋白

使用反应编号和蛋白编号删除一条已选关联，自动、人工来源均可删除：

```powershell
python main.py protein remove -i demo01.json -r R06320 -p Q41594
```

`-p/--protein` 填 UniProt 或本地蛋白编号（如 `MY_ENZYME`），规范为大写，不接受路径。只删除指定 R 下的关联，其余蛋白的顺序、来源、路径以及其他 R 对该蛋白的使用均保留；FASTA 和 JSON 文件不删除，也不联网或补建注释。被删蛋白的文件缺失或损坏仍可移除。指定关联已经不存在时返回 `changed=false`，不重写清单或清理组合。删除不是永久排除，自动检索仍可能再次选中该蛋白。

删除最后一个蛋白会移除该 R 的记录及对应待复核步骤；还有蛋白则保留原待复核标记。全部删空时仍保留路线编号、空的 `reaction_assignments` 和空的待复核列表。旧格式仅在实际删除时转换，保留蛋白必须能从本地恢复；其他清单区段不迁移。

实际删除后清理旧组合 JSON/CSV。该 R 仍有人工蛋白且候选有效时，会同步 v8 固定快照，保留其他反应的候选与排名，可直接重新生成组合。删除最后一个人工蛋白后，该 R 解除固定，剩余自动已选记录保留，但必须重新运行 `main-enzyme` 后再生成组合；旧快照不会被伪装成已完成检索。原本只有自动蛋白的 R 可继续使用有效候选。候选缺失、损坏或过期不阻止删除，返回 `requires_candidate_regeneration=true`；组合入口在清理前拒绝过期输入。清单、候选发布和组合清理失败时完整回滚。此功能未扩展已生成 CDS、表达盒后的失效处理。

Python 接口：`remove_protein_from_reaction(config, *, reaction_id, accession)`，从 `src.protein_selection` 导入；返回变化标记、反应及步骤、蛋白编号、剩余数量、清单路径、候选同步与组合清理结果及重新检索提示，失败抛出明确异常。

#### 替换反应中的一个已选蛋白

`replace` 保留同 R 下其他蛋白，用新本地序列替换指定的一条已选关联：

```powershell
python main.py protein replace -i demo01.json -r R06320 -p Q41594 -f MY_ENZYME.fasta
```

`-p/--protein` 是旧蛋白编号；`-f/--file` 只填新 `.fasta` 文件名，从配置输入目录的 `protein_sequences` 查找，不依赖当前工作目录。编号与序列、注释校验沿用 `add`，支持 UniProt 和本地编号；缺少新 JSON 时补建本地注释，未知字段为 `null`。操作不联网，不删除或覆盖旧 FASTA/JSON。

新蛋白占旧记录的位置，来源设为 `manual`。新编号已经在同 R 下时，移除旧记录，保留新记录原位置和路径并转为人工来源；其他 R 的关联保持不变。同编号同序列可跨反应共享已有文件，优先保留目标 R 已有路径；同编号不同序列报错。旧编号必须存在，因此成功替换后重复原“旧编号→新编号”命令会报错。自替换时自动记录转人工，已是相同人工记录则返回 `changed=false`，不重写或清理文件。

不同编号替换允许被移除旧记录的文件缺失或损坏；新文件、保留记录及同编号自替换的原记录必须可校验。清单只局部更新 `main_enzyme_selection`，旧格式仅在实际替换时转换；该 R 的全部步骤并入待复核列表，整组蛋白作为固定选择。

已有有效候选时同步 v8 固定快照；目标 R 原本只有自动记录时移除其活动自动候选并重算覆盖，其他反应的候选、排名和证据保留。候选缺失、损坏、过期或无法核对旧快照时仍可替换，返回 `requires_candidate_regeneration=true`，先运行 `main-enzyme` 再生成组合。实际变化后清理旧组合 JSON/CSV；注释、候选发布、清单与组合清理统一事务，失败完整回滚。已生成 CDS、表达盒后的失效处理未扩展。

Python 接口为 `replace_protein_in_reaction(config, *, reaction_id, old_accession, sequence_file)`，从 `src.protein_selection` 导入；返回变化标记、新旧编号、反应与步骤、文件路径、剩余数量及候选同步、组合清理和重新检索提示，失败抛出明确异常。

#### 单独下载蛋白氨基酸序列

需要先准备本地蛋白序列时，可以使用 `protein download`。这一步独立于主酶组合选择，不要求已有路线或主酶组合，也不会把下载的蛋白自动写入设计清单。

```powershell
python main.py protein download -i demo01.json --uniprot P22873
python main.py protein download -i demo01.json --name TBT
```

`--uniprot` 和 `--name` 必须且只能提供一个；`-i` 只填写 `inputs` 目录下的配置文件名。按编号时获取对应记录；按名称时查询基因名和蛋白名称并遍历候选，有精确基因名命中时优先在该候选池中选择，没有时才使用蛋白名称候选。在对应候选池内，优先选择与当前底盘分类学最接近且序列有效的蛋白；同分时比较现有证据评分，再按编号稳定排序。名称模式使用配置基因组或清单中的宿主；未指定宿主且使用默认模型时，沿用 MG1655 默认宿主。自定义底盘无法确定时，请补齐基因组配置或改用编号。

下载结果固定保存到 `inputs/protein_sequences/`，以最终 UniProt 编号命名：

- `<accession>.fasta`：单条氨基酸序列。
- `<accession>.json`：蛋白名称、来源物种与 taxon ID、审校状态、辅因子、序列长度、版本、来源 URL、下载时间和 UniProt 原始记录。

程序返回两个文件的绝对路径。默认校验并复用已有且一致的 FASTA/JSON；名称模式每次仍会先查询候选，按当前底盘重新确定编号。文件缺失时联网补齐；损坏或冲突时提示刷新。需要重新获取同编号的最新序列和注释时使用：

```powershell
python main.py protein download -i demo01.json --uniprot P22873 --force
```

更新发生错误时会恢复原文件。下载本身不会修改已选蛋白、生成 CDS 或注册新的宿主。Python 调用方式及输出字段见 [蛋白下载接口说明](protein_download.md)。

### 2.4 生成并查看 CDS

这一步仅为已选主酶准备 DNA 编码序列。新格式清单使用 `sequence_file` 指定的本地氨基酸序列，校验后复制到 CDS 工作目录，并使用 CodonTransformer 生成面向当前宿主的密码子设计。读取主酶注释和分析明细时不会联网；明细缺失或与当前路线不符时，仍可查看基本选择，但需重新生成主酶结果后才能继续 CDS 或表达盒流程。

生成时启用 `match_protein=True`，由模型约束密码子选择以保持蛋白序列一致。对于未修改的模型输出，生成和写入清单时不独立翻译比对，仍检查碱基、长度、起止密码子和内部终止。每次调用重新生成 CDS，生成报告采用 `protein_to_cds.generation.v3`，记录模型约束依据，不再包含序列摘要。未执行的独立翻译检查不代表检查失败。后续通过 `optimize` 调整 CDS 时，仍会独立翻译核对蛋白序列。

```powershell
python main.py protein-to-cds -i demo01.json
python main.py info -i demo01.json --cds
```

系统为每条 CDS 保存两份序列，便于保留初始设计和进行后续调整：

| 序列 | 用途 |
|---|---|
| `raw_cds` | 初始生成或直接上传的 CDS，作为后续调整的参照；不一定是来源物种的天然基因序列 |
| `optimized_cds` | 当前用于构建的 CDS，后续 GC、酶切位点和连续重复碱基调整都作用于这一份 |

初始两份序列相同。文件夹名为 `optimized_cds` 不代表它已经满足所有克隆要求：`protein-to-cds` 不会自动运行下一节的 DNA Chisel 序列调整。

**重新成功执行 `protein-to-cds` 会重新生成初始 CDS，并覆盖当前用于构建的序列，之前通过 `optimize` 做的调整也会被重置。** 已有调整后，使用 `info --cds` 查看结果。

查看初始序列的指标：

```powershell
python main.py info -i demo01.json --cds --raw
```

### 2.5 按克隆需求调整 CDS

如果基因合成或组装对 GC、内部酶切位点或连续重复碱基有要求，可以在这里调整 CDS。程序使用 DNA Chisel，通过同义密码子替换修改 DNA，保持编码的蛋白氨基酸序列不变。

以下功能按需选择，分别执行；表中的数值和酶名都是操作示例，请按自己的构建要求设置：

| 功能 | 命令示例 |
|---|---|
| 将一条 CDS 的整体 GC 含量设为 40%～60% | `python main.py optimize -i demo01.json --cds P21683 --gc-min 40 --gc-max 60` |
| 检查一条 CDS 的每个连续 50 nt 区段，将局部 GC 设为 30%～70% | `python main.py optimize -i demo01.json --cds P21683 --gc-min 30 --gc-max 70 --window 50` |
| 去除所有 CDS 内部的 EcoRI、HindIII 识别位点，为后续克隆保留这两种酶 | `python main.py optimize -i demo01.json --enzyme EcoRI HindIII` |
| 限制所有 CDS 中连续相同碱基的长度，最多允许 6 个 | `python main.py optimize -i demo01.json --homopolymer-max 6` |

- `--cds` 后填要调整的蛋白编号，可从 `info --proteins` 查看。
- GC 单位是百分比；`--window` 的单位是 nt（碱基数），必须为正整数且不超过 CDS 长度。
- “同聚物”就是连续相同碱基，例如 `AAAAAAA`。最大长度 6 表示允许连续 6 个，7 个及以上需要打断。
- 酶名忽略大小写；未指定酶时，不会自动选择要去除的酶切位点。`--enzyme none` 只清空酶选择，不会恢复已修改的序列。
- GC 调整、酶切位点去除、连续重复碱基调整三类操作分开执行；后续调整还必须满足之前已经设定的其他要求。

调整会保持编码蛋白、CDS 长度和原始起止密码子不变。如果要求之间冲突、无法同时满足，本次调整不保存，原先用于构建的 CDS 会保留。

完成后运行 `python main.py info -i demo01.json --cds` 复查。没有这些调整需求时，可以直接进入表达盒分组；若准备使用第 2.9 节的网页双酶切设计，需先指定两种组装酶并完成相应位点检查。

### 2.6 选择表达盒分组

这一步回答：“哪些基因共用一个启动子和终止子，哪些基因分开表达？”分组同时决定每个表达盒中 CDS 的排列顺序。

先生成分组建议，再选择分组方案 1，最后查看具体分组：

```powershell
python main.py expression --design --box -i demo01.json
python main.py write -i demo01.json --expression-box 1
python main.py info -i demo01.json --expression-box
```

例如，两个基因放在同一表达盒时，结构为“启动子—RBS—CDS 1—RBS—CDS 2—终止子”；放在不同表达盒时，每个表达盒分别配置启动子和终止子。每个 CDS 分别编码对应的蛋白。

此时只确定分组，下一步才配置具体的启动子、RBS 和终止子。已有表达安排时，也可使用 [自定义分组](#35-自定义表达盒分组)。

### 2.7 上传表达元件

如果已经有实验室常用的表达元件，可以上传自己的 DNA 序列。若希望系统推荐元件，请改用 [元件推荐](#36-使用系统推荐元件)，完成确认后直接进入第 2.8 节。

将元件序列文件放在 `inputs/parts/` 文件夹。每个表达盒需要一个启动子和一个终止子，每个蛋白需要一个 RBS。元件与命令参数的对应关系如下：

| 元件 | 作用 | 上传时填哪个编号 |
|---|---|---|
| 启动子（promoter） | 控制该表达盒的转录起始 | 表达盒编号 |
| RBS | 控制对应 CDS 的翻译起始 | 蛋白编号 |
| 终止子（terminator） | 结束该表达盒的转录 | 表达盒编号 |

下面示范为表达盒 1 和蛋白 `P21683` 上传元件：

```powershell
python main.py expression -i demo01.json --promoter 1 promoter_1.txt
python main.py expression -i demo01.json --rbs P21683 rbs_1.txt
python main.py expression -i demo01.json --terminator 1 terminator_1.txt
```

这里的 `1` 是已选分组中的**表达盒编号**，不是分组方案编号；`P21683` 是该表达盒中某个蛋白的编号。对其余表达盒和蛋白重复上传，直到元件齐全。

文件要求：

- 参数只填 `inputs/parts` 下的文件名。
- 支持 `.txt`、`.fa`、`.fasta`、`.fna`；TXT 放 DNA 序列，FASTA 只放一条记录。
- 序列只能包含 A、C、G、T，空白和大小写会自动处理。
- 同一表达盒或蛋白位置再次上传同类元件，会替换该位置已有的元件。
- 上传 RBS 时，程序会结合相邻 CDS 序列预测翻译起始率。该数值用于比较设计，不等同于实测蛋白表达量；预测失败时不保存此次 RBS 上传。

上传后查看是否还有元件缺失、RBS 预测是否成功，以及序列是否存在冲突：

```powershell
python main.py info -i demo01.json --expression-box
```

### 2.8 构建完整表达序列

这一步把已经选好的元件和 CDS 拼成完整的 DNA 序列，供后续接入质粒。无论使用上传元件还是系统推荐元件，都执行同一个命令：

```powershell
python main.py expression -i demo01.json --assemble
```

每个表达盒按下面的顺序拼接，同一方案中的全部表达盒再按编号串联：

```text
启动子 + RBS₁ + CDS₁ + RBS₂ + CDS₂ + … + 终止子
```

程序使用当前 `optimized_cds` 中的序列。如果 CDS 或相邻序列已经变化，会重新计算受影响的 RBS 预测，并检查完整序列及元件连接处是否出现已指定的限制酶位点或过长连续重复碱基。

完整表达序列的整体和局部 GC 在这里仅作统计，不自动调整。缺少元件、RBS 预测失败或存在序列冲突时，不会保存新的完整构建；应按提示处理对应序列后再运行本步骤。

成功后导出 `expression_constructs/design_001.gb` 等文件，并写入项目记录。`.gb` 是带有基因和元件位置注释的 GenBank 文件，可在支持该格式的序列软件中查看。

如果选了多个元件方案，每个方案分别生成一个构建文件。此时得到的是**待插入质粒的完整表达序列**，尚未添加用于接入质粒的克隆末端，也不是完整质粒。

### 2.9 选择质粒并完成理论组装

完成表达序列后，可以选择下面两种方式之一：在网页中自己搭配质粒模块，或在命令行中使用系统推荐的质粒骨架。

#### 方式 A：在网页中自己搭配质粒模块

网页适合希望自己选择抗性、复制模块和模块排列顺序的用户。网页根据选定元件进行理论序列组装，宿主信息仅作项目记录，不用于限制进入、筛选元件或判断兼容性。**当前网页设计要求只有一个已确认的完整表达构建。** 还需在前面的 CDS 调整步骤中，通过 `optimize --enzyme` 指定恰好两种不同的常规黏性末端酶，再重新执行 `expression --assemble`。

例如，确定使用 EcoRI 和 HindIII 后，可按以下顺序准备并打开网页：

```powershell
python main.py optimize -i demo01.json --enzyme EcoRI HindIII
python main.py expression -i demo01.json --assemble
python main.py web -i demo01.json
```

如果已经使用这两种酶完成检查和表达构建，只需启动网页：

```powershell
python main.py web -i demo01.json
```

浏览器会自动打开。可以按下面的顺序操作：

1. **选择抗性模块**，用于后续筛选携带质粒的细胞。
2. **选择复制模块**，确定质粒的复制相关配置。复制模块只保留一个，再次选择会替换原模块。
3. **按需加入 T0、T1 终止子**。它们在“终止子”分类中手动添加，参考位置为 `T1 → 完整表达构建 → T0`。这两者属于质粒层面的终止子，与前面各表达盒内的终止子分开配置。
4. **调整模块顺序**。可按住圆环色块或右侧列表行拖动，圆环与列表同步更新。
5. **点击“生成设计”并检查提示**。缺少 T0、T1 或位置不符合参考安排时，会弹出警告，可选择“返回调整”或“继续生成”。继续生成仅使用当前选入的序列，不会自动补入缺失终止子；酶切冲突等错误仍需先解决。
6. **导出结果**，包括 GenBank 文件、制备片段和报告。结果会写入项目记录，文件保存在 `plasmid_designs/`。

每次点击抗性模块或终止子，或将其从组件库拖入圆环、右侧列表，都会在列表末尾新增一个独立副本。**同一个模块可以重复添加，每个副本都会进入实际质粒序列和导出文件**；如不需要重复，应删除多余副本。各副本可以分别删除和排序，刷新页面后保留已有副本及顺序。

“间隔区段”分类仅提供 **BASIC L1～L6**，每条为 53 bp。可按需添加到独立功能模块之间，再调整位置或删除；纯序列拼接允许重复添加。程序只包含明确选入的 Gap，未选时不插入间隔，也不自动补入旧方案中的 76/14 bp 片段。临时骨架占位使用 BASIC L1，生成最终质粒时由完整表达构建替换。

程序保留上传元件、当前完整表达构建和明确选入的组件，并在表达构建两端补齐组装所需酶切位点。如果模块或构建内部存在额外的所选酶位点，需要更换酶或模块；更换酶后应重新完成 CDS 位点检查和完整表达构建。

使用完毕后，在启动网页的 PowerShell 窗口按 Ctrl+C 停止服务。端口被占用时可运行 `python main.py web -i demo01.json --port 8001`。

#### 方式 B：使用系统推荐的质粒骨架

先推荐骨架，根据结果选择一个。示例选择候选 1：

```powershell
python main.py plasmid --recommend -i demo01.json
python main.py write -i demo01.json --plasmid 1
```

随后生成组装计划，查看终端中的插入位置、组装方法和片段信息，确认后接受计划并导出组装结果：

```powershell
python main.py assembly --plan -i demo01.json
python main.py write -i demo01.json --assembly-plan
python main.py assembly --execute -i demo01.json
```

系统自动选择可行的 Gibson 或双酶切方法。组装计划必须完整才能接受；需要指定方法或抗性时，见 [可选参数速查](GLADE部署教程.md#8-可选用法速查)。

这里的 `assembly --execute` 是**在计算机中生成最终序列和文件**，不会执行实际酶切、连接或转化实验。

主要交付结果位于 `final_assembly/`：

- `design_001_final.gb`：带基因、元件及位置注释的完整质粒，便于检查设计。
- `design_001_final.fasta`：完整质粒的 DNA 序列。
- `final_design_report_zh.md`：中文设计报告，用于查看构建和组装信息。

以上是理论设计交付文件。进入实验前，应复核序列和注释，并按所选方法制备片段、完成构建和验证。

## 3. 可选功能

### 3.1 扩展底盘可达集合

如果从原始底盘前体出发找不到合适路线，可以进一步问：“假如补充一些反应，底盘还能提供哪些新的前体？”这就是扩展底盘可达集合。

下面以扩展深度 1 为例，先预测新增可用前体，再基于扩展后的结果搜索路线：

```powershell
python main.py expand -i demo01.json -d 1
python main.py gap -i demo01.json -d 1
python main.py info -i demo01.json --gap -d 1
```

扩展深度必须大于等于 1，表示底盘前体集合向外扩展的层数。它不同于从前体到目标的合成路线步数。

**扩展出的前体需要补充相应反应，并满足反应计量与底物供给条件，不表示原始菌株天然具有这些能力。** 选用这类路线时，应把前体供给所需的改造也纳入实验设计；查看、验证和确认该批路线都使用同一个 `-d 1`。

### 3.2 验证路线

通量验证回答：“将这条路线加入当前代谢模型后，在给定培养基和约束条件下，是否允许代谢流流向目标？”它用于检查反应网络中的供给或辅因子问题，不是测定酶活或预测实际发酵产量。

下面对路线 1 单独验证，并使用严格辅因子条件：

```powershell
python main.py validate -i demo01.json -s 1 -m per -c strict -d 0
```

其中，`-s 1` 指定路线编号，`-m per` 表示各路线分别验证，`-c strict` 表示使用严格辅因子模式，`-d 0` 必须与路线搜索深度一致。

纯 KEGG 路线支持两种顺序：先验证候选，再用 `write --solution N` 选用时带入已有结果；或先写入路线，再验证该路线，由 `validate` 自动更新 `solution.validation`。例如当前已经选择路线 1，可直接运行放宽辅因子模式：

```powershell
python main.py validate -i demo01.json -s 1 -c relaxed -d 0
```

验证当前已选路线后无需再次 `write`。自动回写仅更新验证区段，保留路线、蛋白及 CDS、表达盒等下游记录。同一路线保留最新完成的单路线验证结果，strict 和 relaxed 可以相互覆盖，通过和失败都如实记录；`relaxed` 的通过结论仅适用于已放宽的辅因子条件。

尚未选择路线、验证其他路线或仅运行 `-m pooled` 时，只生成报告；`-m both` 使用对应的单路线结果回写。回写会核对当前目标、路线、深度、目录及步骤；验证期间路线、模型、培养基或步骤输入发生变化时，保留报告并提示未回写。计算异常或发布失败保留原清单，返回结果中的 `manifest_updated` 和 `manifest_update_message` 说明本次是否更新及原因。

已选路线的验证摘要及通量明细保存在验证目录的 `selected_solution_<编号>` 子目录，清单保存相对路径；后续验证其他候选不会覆盖这些明细。相同内容不重写清单和明细，同一项目、同一深度的验证不能并行运行。本次自动回写仅适用于纯 KEGG 路线，RetroPath 沿用原有行为。

- **验证通过**：路线在当前模型条件下具有通量可行性，后续仍需确认具体酶和实验条件。
- **验证失败**：应检查模型中的前体供给、反应方向和辅因子条件，也可能存在模型或反应映射缺失；不能仅据此认定实验一定失败。
- **未验证**：表示还没有这项模型证据，不等于已经通过。

验证失败或未验证的路线仍可用 `write` 确认选用，但需要人工复核。多路线验证见 [验证速查](GLADE部署教程.md#8-可选用法速查)，RetroPath 验证数据准备见 [部署教程](GLADE部署教程.md#33-mnxref)。

### 3.3 使用 RetroPath

RetroPath 根据化学结构和反应规则，从目标向前寻找可能的合成路线，可作为默认 KEGG 搜索之外的补充。这类预测路线需要进一步检查各步反应和酶证据。

先按 [部署教程](GLADE部署教程.md#32-retropath-规则与服务) 启动本地服务，再运行：

```powershell
python main.py gap -i demo01.json --retropath -d 0
python main.py info -i demo01.json --gap -d 0
python main.py info -i demo01.json --retropath-candidate 1 -d 0
```

候选详情会给出对应的 **GLADE 路线编号**。后续查看、验证和 `write --solution` 都使用这个编号，不要直接使用 RetroPath 候选排名，两者可能不同。

默认最多预测 3 步，可在搜索命令中加入 `--step 5` 改为最多 5 步。这里的 `--step` 是 RetroPath 预测步数，与底盘扩展深度 `-d` 含义不同。

### 3.4 自定义表达盒分组

已有明确的共表达安排时，可以直接指定分组。每个方括号表示一个表达盒，括号内蛋白编号的顺序就是 CDS 的排列顺序：

```powershell
python main.py expression --design --box -i demo01.json --custom [P00001 P00002] [P00003]
```

示例将 `P00001`、`P00002` 放在同一个表达盒中，将 `P00003` 单独放在另一个表达盒中。请替换为自己的蛋白编号，当前名单中的全部蛋白必须恰好出现一次，不能遗漏或重复。

该命令直接保存分组，无需再执行 `write --expression-box`。之后回到第 2.7 节准备元件。

### 3.5 使用系统推荐元件

如果没有准备自己的启动子、RBS 和终止子，可以让系统从已配置的元件库中推荐组合。需要部署教程中说明的元件库服务。

下面两条命令替代第 2.7 节的手动上传：先生成推荐，再确认方案 1。之后回到 [构建完整表达序列](#28-构建完整表达序列)：

```powershell
python main.py expression --design --parts -i demo01.json
python main.py write -i demo01.json --expression-parts 1
```

每个方案是一套覆盖已选表达盒的启动子、RBS 和终止子组合。默认请求 12 个方案；`write` 只保存选择，不立即生成 GenBank 文件，仍需执行 `expression --assemble`。

可同时选择多个方案，例如 `--expression-parts 1:3` 表示选择方案 1、2、3，便于比较不同元件组合。如果后续使用网页搭配质粒模块，目前需只确认一个方案。

重新运行推荐会重新计算，并使原先确认的计算结果及后续构建失效，需要重新确认方案。上传元件和人工准备信息保留。推荐评分、RBS 翻译起始率和表达负担估算用于筛选设计，不等同于实际表达量或产物产量。表达负担表示程序估计的宿主表达资源消耗；上传元件缺少活性数据时，会采用有记录的中性估算，这不代表已经测定其负担。

## 4. 结果与重新运行

当前流程仅设计已选主酶。主酶、CDS、表达盒/元件、质粒推荐、组装计划和网页设计的计算产物格式已更新，不再包含文件或内容指纹。旧计算结果及确认记录需要重新生成或确认；遇到格式过期提示时，从提示指定的阶段继续。历史文件保留，程序不会批量删除缓存或输出目录。

重新计算前，本阶段及受影响的下游当前结果引用会失效。新运行失败时，查看和下载入口不会把上次成功结果当成本次结果。网上查询缓存、下载的蛋白 FASTA 和原始质粒数据继续保留；缓存缺少旧摘要或摘要不匹配不会触发重新下载，仍会检查格式、编号、序列和结构。旧上传草稿中的人工信息继续可读，其中的预测需要重新执行。

如果使用底盘扩展或 RetroPath，遇到版本不匹配提示时，先重新生成对应的扩展或路线结果。

主酶组合只按反应匹配、方向、特异性与蛋白证据评价。反应方程和 GEM 验证保留完整的辅因子计量；路线不再生成独立的电子风险评分或载体平衡摘要，也不向设计清单写入这些字段。重新确认路线或主酶组合时，会清除设计清单中的旧电子评估区段。

旧版底盘扩展和 RetroPath 路线结果需重新生成，以更新扩展策略和路线文件格式。KEGG 路线的查看、确认不再依赖电子评估文件；历史结果文件保留，重新运行 KEGG 搜索时会清理对应深度目录中的旧电子评估 CSV。旧配置项 `electron_avoidance_mode` 已停止参与计算。

### 常用结果位置

结果统一保存在 `outputs/C00811/`，其他目标使用自己的化合物编号。下表路径都相对于这个文件夹：

| 内容 | 相对该目录的位置 |
|---|---|
| 底盘模型预测可提供的代谢物 | `chassis_result/producible_kegg_compounds.csv` |
| 路线列表 | `kegg_gap_C00811/depth0/solutions.csv` |
| 初始生成或上传的 CDS | `protein_to_cds/raw_cds/` |
| 当前用于构建的 CDS | `protein_to_cds/optimized_cds/` |
| 完整表达构建 | `expression_constructs/` |
| 最终质粒与设计报告 | `final_assembly/` |
| 网页生成的质粒设计 | `plasmid_designs/` |
| 已选方案、项目状态和结果文件位置 | `design_manifest.json` |

日常通过 `info` 查看结果即可，不需要手动编辑 `design_manifest.json`。CSV 文件用于查看表格，FASTA 文件用于查看序列，GenBank 文件同时保存序列和元件注释。

**结果按目标化合物编号归档，而不是按配置文件名分开。** 两个配置文件如果使用相同目标编号，会使用同一个目标结果目录；保存不同版本设计时，请先备份对应结果目录。

### 改了设计后，从哪一步继续

路线、蛋白、CDS、元件和质粒之间前后关联。例如，更换某个蛋白会改变对应 CDS，原来的 RBS 预测和构建也可能不再适用。修改后按下表继续，不要直接使用旧的最终质粒文件。

| 修改内容 | 后续操作 |
|---|---|
| 更换路线 | 重新选择主酶，并执行后续流程 |
| 更换主酶组合 | 重新生成 CDS、确认分组并准备元件，再构建和组装 |
| 调整或重新生成 CDS，蛋白名单和分组仍有效 | 分组和元件可保留；重新 `expression --assemble`，再设计质粒并组装 |
| 修改表达盒分组 | 重新配置元件，再构建、选择质粒并组装 |
| 上传或更换元件、确认不同元件方案 | 重新构建、选择质粒并组装 |
| 更换质粒骨架 | 重新生成、接受并执行组装计划 |

路径扩展、RetroPath、路径 benchmark，以及主酶、CDS、表达设计、质粒推荐和组装计划每次重新计算，不复用上次的计算结果。KEGG 文本、MOL、网上查询和原始下载数据的本地缓存继续读取。业务 ID、环形序列去重、确定性随机种子、缓存定位键、并发锁和自定义模型输出目录所用的哈希保留；文件路径和目录约定不变。**`protein-to-cds` 会重置当前用于构建的 CDS**，之前的序列调整需要重新执行。

“结果已过期”或“失效”表示生成该结果所依据的设计已经改变。例如，旧表达构建使用的是修改前的 CDS；此时应重新完成提示指定的步骤。

## 5. 常见问题

| 问题 | 处理方法 |
|---|---|
| 找不到配置文件 | 确认文件在 `inputs` 文件夹中，扩展名为 `.json`；`-i` 后只填文件名 |
| 目标格式错误 | `target_name` 填大写 `C` 加五位数字，例如 `C00811`，不能填化合物名称 |
| 提示目标已经可供给 | 这是当前模型的正常判断；结合实际菌株和检测结果确认，不代表产量已满足需求 |
| 没有候选路线 | 先检查目标编号、底盘和培养基结果，再尝试底盘扩展或 RetroPath；未找到不等于不存在合成途径 |
| 提示结果已过期 | 按提示从需要更新的步骤继续；同一批路线的搜索、查看、验证和确认保持相同 `-d` |
| 主酶检索或推荐服务失败 | 检查网络及服务配置，见 [部署教程](GLADE部署教程.md)；服务失败不等于没有合适的酶或元件 |
| DNA Chisel 要求无法满足 | 按提示检查 GC 范围、窗口大小和要求之间是否冲突；历史文件保留，但当前计算结果及受影响的下游引用会失效 |
| RBS 上传预测失败 | 检查 RBS 序列及相邻 CDS 是否符合输入要求、CDS 是否完整，按提示处理后重新上传 |
| 完整表达序列出现酶切位点或连续重复碱基冲突 | 按提示的位置和元件名称处理对应 CDS 或上传元件；拼接处也可能产生新位点，处理后重新 `expression --assemble` |
| 网页提示项目尚未准备好 | 确认仅有一个完整表达构建，并已指定两种适用组装酶；修改后重新构建 |
| `protein-to-cds` 退出码为 2 | 表示本次 CDS 处理未全部完成，查看目标结果目录下 `protein_to_cds/run_summary.json` 中记录的失败原因 |

如果需要查看某条命令还有哪些参数，可在命令后加入 `--help`。这只显示帮助，不会运行设计步骤：

```powershell
python main.py --help
python main.py optimize --help
```

部署与服务配置见 [部署教程](GLADE部署教程.md)，详细验证和更多参数见其中的 [可选用法速查](GLADE部署教程.md#8-可选用法速查)。
